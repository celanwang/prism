## 校准对照与客户端开销

偏差=(模拟p99−实测p99)/实测p99。两侧使用同一请求时刻/长度、seed、λ、C、Q、窗口和超时；模拟使用 P1-T4 校准的 prefill 斜率和 decode(1)，不是重新拟合 HTTP。
适配器在去掉 C 限制时逐点校验原 T3 的完成/拒绝、分位数与雪崩判定。有限 C 模型假设 HTTP/429 零耗时；实测有线程、socket、解析和 tracing 扰动。
prefill 固定截距仍省略，decode 仅 context=32 标定；不外推生产服务。
客户端有 C 个预启动线程和至多 C 个 socket，服务 Connection: close，逐请求重连。满池到达立即丢弃，无隐藏请求队列/重试。低 C 下的低吞吐可能来自客户端限流。
rounds.json 单独保存 dispatch/client thread CPU/transport residual 的分位数、进程 CPU、队列采样间隔；residual=wire−queue_wait−inference，包括传输与服务 HTTP 开销，不冒充纯客户端耗时。

## 边界声明

单进程串行推理、CPU 小模型、loopback、无 TLS。同进程客户端与服务竞争资源；只测整包响应，流式等价性与 TTFT 见 P3-T1 PR #12。
队长为定时采样近似，短暂变化可能漏采；bounded Q 与有限 C 限制增长，未触发不证明稳定。时延仅含成功请求，须连同429/超时/客户端满计数解释。
无独立进程重复或置信区间，smoke test 不等于实验证据。
